# Audit Coverage Matrix

## Purpose

RB-116 keeps mutation-path audit coverage explicit and reviewable. This matrix is both documentation and the source for `tests/unit/audit-coverage-matrix.test.ts`.

## Classification Rules

- `AuditLog` is required when a user or operator changes governance, permissions, cleanup deletion state, or other state not already captured by a durable append-only domain artifact.
- Append-only domain rows are sufficient when they include stable IDs, timestamps, user attribution, and provenance fields.
- Queued job rows are sufficient only when they preserve requester/trigger context and processing outcome.
- Processor logs alone are not sufficient durable audit evidence.
- Cleanup dry-runs and consistency reports are operational findings; execute-mode deletions must be attributable.
- High-cost rate-limit buckets are classified technical state writes and are exempt from user-facing audit events.
- Future unattended worker runs and SaPen Core handoff must not rely on anonymous or nullable user fields.
